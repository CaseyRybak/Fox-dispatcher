# Продуктовая спецификация: «Лисий диспетчер»

Статус: действующий контракт реализованного продукта

Сценарий: интерактивная панель лесного смотрителя

План реализации: [2026-07-16-fox-dispatcher-implementation.md](../exec-plans/completed/2026-07-16-fox-dispatcher-implementation.md)

## Цель продукта

«Лисий диспетчер» помогает лесному смотрителю работать с набором наблюдений: понять, сколько лис замечено, какая локация является основной, какая лиса лидирует по объяснимому индексу подозрительности и из каких исходных признаков сложился результат.

Интерфейс демонстрирует изменение результата двумя путями:

- изменение самих наблюдений;
- изменение явной политики оценки — влияния признака добычи.

Результат представляет собой связанную систему: главный вывод, рейтинг, основная локация, пояснение формулы и отдельный журнал исходных записей.

## Пользователь и основной сценарий

Основной пользователь — лесной смотритель, которому нужно быстро оценить текущую выборку наблюдений и проверить основания вывода.

Целевой сценарий проверки:

1. Открыть приложение и без настройки увидеть стартовые данные.
2. Считать 5 наблюдений, 4 уникальные лисы и главную локацию.
3. Увидеть лидера `fox_001` с индексом 7,8.
4. Открыть расчёт этой лисы.
5. Изменить влияние добычи с 20% на 30%.
6. Увидеть новым лидером `fox_003` с индексом 7,9.
7. Открыть AI Worklog и проверить процесс разработки по артефактам.
8. При наличии should-have управления изменить наблюдение и увидеть синхронный пересчёт всех частей отчёта.

## Поля и их семантика

| Поле | Значение в продукте | Вклад в индекс |
|---|---|---:|
| `id` | Уникальный технический идентификатор наблюдения | Нет |
| `fox_id` | Идентификатор, объединяющий наблюдения одной лисы | Только группировка |
| `fox_name` | Сохраняемое пользовательское имя лисы; для стартовых данных выводится из канонического ID | Нет |
| `location` | Зафиксированное название места наблюдения | Нет |
| `color` | Закреплённый цвет лисы, повторяемый в её наблюдениях | Нет |
| `has_prey` | Наблюдаемый факт наличия добычи | Да |
| `suspicion_level` | Уровень подозрительности, выставленный смотрителем | Да |
| `time` | Время записи внутри текущей выборки | Нет |

Стартовым записям без `fox_name` интерфейс выводит читаемое имя из канонического `fox_NNN`: `fox_001` становится `Лиса 1`. Ручное добавление принимает имя, а не ID. Совпадение имени без учёта регистра и лишних пробелов повторно использует существующий `fox_id`; новое имя получает первый свободный `fox_NNN` и сохраняется отдельно. Рядом с именем интерфейс показывает технический `fox_id`. Поиск принимает имя или ID.

`location`, `color` и `time` дают контекст, фильтрацию и хронологию. Количество записей одной лисы показывает объём доказательств. Эти значения не получают скрытых коэффициентов.

Цвет закрепляется за лисой по её первому наблюдению в активном наборе. При ручном добавлении или редактировании записи существующей лисы приложение подставляет этот цвет и не принимает другое значение. Форма сообщает: `Для данной лисы уже задан цвет XXX`. Сообщение информационное и не блокирует сохранение.

## Значение «текущей выборки»

Данные содержат время, но не дату. Продукт называет расчёт `текущей выборкой` или `текущим набором наблюдений`.

Время используется для:

- сортировки записей;
- определения последнего наблюдения;
- разрешения равенства в рейтинге.

Время не означает давность в днях и не создаёт recency-бонус. Формулировки про буквальное «сегодня», live-состояние или вероятность будущего поведения не входят в продуктовый контракт.

## Объяснимая модель оценки

### Назначение индекса

Индекс подозрительности — число от 0 до 10 для относительного приоритета внимания внутри активной выборки. Это не вероятность опасности и не автоматическое обвинение.

### Агрегаты лисы

Для каждой лисы `f`:

```text
meanSuspicion(f) = среднее suspicion_level всех записей f
preyRate(f)      = записи f с has_prey=true / все записи f
preySignal(f)    = preyRate(f) × 10
```

### Формула

```text
score(f) =
  meanSuspicion(f) × (1 − preyWeight)
  + preySignal(f) × preyWeight
```

Начальное нормализованное значение `preyWeight = 0.20`. Каноническая политика хранит целое `preyWeightPercent = 20`; пользователь меняет его от 0 до 100 с шагом 5, а для формулы используется `preyWeight = preyWeightPercent / 100`. Вес прямой оценки автоматически равен `1 − preyWeight`.

Текст рядом с настройкой объясняет допущение: добыча считается настраиваемым сигналом диспетчерского внимания. При весе 0% рейтинг буквально следует только `suspicion_level`.

Сводка явно объясняет семантику количества: индекс использует все наблюдения лисы, поэтому их количество влияет на среднюю подозрительность и долю наблюдений с добычей, но не является самостоятельным сигналом и само по себе не добавляет баллы. Цвет, локация и время не входят в формулу. После принятого изменения веса пользователь видит прежний и новый процент, нового лидера или весь набор со-лидеров, подтверждение неизменности результата и новый индекс.

Верхняя карточка показывает лидера или всех лис с математически равным максимальным индексом, две части индекса для каждой из них, число уникальных лис и основную локацию. Со-лидеры перечисляются полностью: `Лисы 3 и 5`, а при трёх результатах — `Лисы 2, 3 и 5`; детерминированные tie-breaks задают их порядок в рейтинге, но не скрывают ничью. Следующий отдельный блок объясняет расчёт простым языком отдельно для каждого со-лидера в трёх частях: средняя подозрительность по всем наблюдениям, наличие добычи и сложение частей. Действие `Изменить параметры` открывает раздел `Параметры`. Рядом находится отдельная кнопка `Изменить вес параметров`; она переводит клавиатурный фокус на настройку `Влияние добычи`.

### Сортировка и округление

Рейтинг сортируется по:

1. неокруглённому `score`, по убыванию;
2. `meanSuspicion`, по убыванию;
3. времени последнего наблюдения, от позднего к раннему;
4. `fox_id`, лексикографически по возрастанию.

Интерфейс показывает один знак после запятой. Порядок определяется исходным неокруглённым значением, поэтому вычисление остаётся стабильным.

Расчёт и сравнение не используют двоичное округление `Number` как источник истины. Вес хранится целым числом процентов `w` от 0 до 100 с шагом 5. Для лисы с `n` наблюдениями:

```text
scoreNumerator = sumSuspicion × (100 − w) + preyCount × 10 × w
scoreDenominator = n × 100
```

Два индекса сравниваются перекрёстным умножением числителей и знаменателей, а средние оценки — перекрёстным умножением `sumSuspicion / n`. При лимите в 1000 записей эти операции остаются в диапазоне безопасных целых JavaScript. Отображение округляет точную дробь до одного знака по правилу decimal half-up, поэтому точное `7,45` показывается как `7,5`, а не зависит от представления IEEE-754.

Для полного детерминизма используются дополнительные порядки:

- `fox_id`, `id` и названия локаций сравниваются ordinal-порядком UTF-16, без locale-зависимого `localeCompare`;
- наблюдения сортируются по `time` от позднего к раннему, затем по `id` по возрастанию;
- локации сортируются по числу наблюдений по убыванию, затем по названию по возрастанию; при пустой выборке ведущей локации нет.

### Стартовый результат 80/20

| Лиса | Средняя подозрительность | Доля добычи | Значение подозрительности в индексе | Значение добычи в индексе | Итог |
|---|---:|---:|---:|---:|---:|
| `fox_001` | 8,5 | 50% | 6,8 | 1,0 | **7,8** |
| `fox_003` | 7,0 | 100% | 5,6 | 2,0 | **7,6** |
| `fox_002` | 5,0 | 0% | 4,0 | 0,0 | **4,0** |
| `fox_004` | 3,0 | 0% | 2,4 | 0,0 | **2,4** |

### Демонстрационный пересчёт 70/30

При `preyWeight = 0.30`:

```text
fox_003 = 7.0 × 0.70 + 10 × 0.30 = 7.90
fox_001 = 8.5 × 0.70 + 5 × 0.30  = 7.45
```

Лидером становится `fox_003`; в интерфейсе его значение отображается как 7,9.

## Состав отчёта

### Сводные показатели

Стартовая выборка даёт следующие значения отчёта:

- 5 наблюдений;
- 4 уникальные лисы;
- 3 локации во внутреннем агрегате;
- основная видимая локация — Северная поляна, 3 из 5 наблюдений;
- факторы индекса — средняя подозрительность по всем наблюдениям и наличие добычи;
- лидер рейтинга — `fox_001`, 7,8 при политике 80/20.

### Рейтинг

Для каждой лисы отчёт предоставляет:

- позицию;
- `fox_id`;
- итоговый индекс;
- среднюю подозрительность;
- количество записей с добычей и общее количество;
- время и место последней записи;
- закреплённый цвет лисы;
- объём доказательств.

### Объяснение выбранной лисы

Подробность содержит:

- итоговый балл;
- оба вклада, округлённые для отображения до десятых;
- текущую политику весов;
- количество наблюдений как контекст;
- явный перечень полей, которые в индекс не входят.

Вклады и итог вычисляются из рациональных значений доменного отчёта, но интерфейс единообразно показывает их десятичными числами до одного знака. Все видимые формулы используют знак `=`, а для периодических результатов рядом выводится пояснение «Значения округлены до десятых». Сравнение и порядок рейтинга продолжают использовать точные дроби, поэтому визуальное округление не влияет на лидера.

## Приоритеты поставки

Базовый публичный релиз содержит точные стартовые данные, интерактивный параметр и пересчёт, понятный рейтинг и объяснение, основную локацию в сводном показателе, 5-7 реальных AI Worklog checkpoints, reviewer README, GitHub-репозиторий и публичный Vercel URL.

Добавление, редактирование, удаление, undo, starter reset и простое локальное сохранение начинались как should-have улучшения. JSON import/export, raw-value recovery и future-version storage были отдельно авторизованным stretch-расширением Phase 8. Они реализованы после готовности базового релиза и не меняют основной продуктовый контракт.

## Область фильтрации

Глобальные фильтры:

- поиск по отображаемому имени лисы или `fox_id`;
- локация;
- цвет;
- добыча: все / есть / нет.

Фильтры определяют область отчёта на Сводке: сводные числа, рейтинг и расчёт выбранной лисы вычисляются из отфильтрованного набора. Редактируемый журнал в разделе `Параметры` всегда показывает полный принятый набор и не входит в эту область фильтрации.

Поиск удаляет окружающие пробелы и выполняет регистронезависимое вхождение подстроки по отображаемому имени или `fox_id`. Группировка лис и уникальность идентификаторов остаются регистрозависимыми: `fox_001` и `FOX_001` — разные доменные значения. Фильтры локации и цвета сравнивают точные нормализованные значения, а их варианты строятся из полного активного набора данных, чтобы комбинирование фильтров не удаляло уже выбранный вариант из control.

В панели фильтров Сводки интерфейс показывает `Показано лис: X из Y`, где оба значения считаются по уникальным `fox_id`: `X` относится к текущей выборке, `Y` - к полному набору. Там же активные фильтры представлены удаляемыми элементами, а общий сброс возвращает полный набор отчёта. В журнале раздела `Параметры` подпись таблицы показывает `Всего наблюдений: X` для полного принятого набора записей. Раздел не отображает состояние фильтров Сводки и не предлагает управлять ими; при возвращении на Сводку выбранные фильтры сохраняются.

## Выбор лисы для инспектора

При первом непустом отчёте выбирается текущий лидер. Явный выбор пользователя сохраняется при изменении веса и других пересчётах, пока эта лиса остаётся в активной выборке. Если фильтр, удаление или замена набора исключили выбранную лису, инспектор выбирает текущего лидера; при пустой выборке выбранной лисы нет. Автоматическая смена не перемещает клавиатурный фокус и сообщается через общий polite status.

Под заголовком `Рейтинг лис` интерфейс предлагает выбрать лису для отображения расчётов. Справа расчёт выбранной лисы и настройка весов находятся в отдельных карточках `Расчет индекса` и `Вес параметров`. Настройка показывает `Влияние подозрительности`, `Наличие добычи`, инструкцию `Измените вес параметров` и действие `Сбросить значения`, возвращающее стартовые 80/20.

## Управление наблюдениями — should-have

Навигационная ссылка и `document.title` используют название `Параметры`, а видимый `h1` страницы — `Наблюдения`. Так пользователь попадает в область управления параметрами продукта и сразу видит, что редактирует именно полевой журнал. Таблица подписана `Всего наблюдений: X`; её числовой столбец называется `Подозрительность`.

### Добавление

Пользователь вводит имя лисы, `location`, `color`, `has_prey`, `suspicion_level` и `time`. Если нормализованное имя уже существует, запись получает его `fox_id`, а цвет автоматически заменяется закреплённым цветом этой лисы даже при вызове application service в обход формы. В форме поле цвета становится read-only и получает связанную информационную подсказку. Новое имя получает первый незанятый ID по возрастанию в формате `fox_NNN`. Наблюдение аналогично получает первый незанятый `obs_NNN`. Оба технических ID создаются приложением и не вводятся пользователем.

Аллокация учитывает точные ID активного набора и заполняет числовые пропуски. Например, после `obs_001` и `obs_003` новая запись получает `obs_002`; при `fox_001` и `fox_003` новая лиса получает `fox_002` независимо от введённого имени.

Принятое наблюдение немедленно обновляет отчёт и сохраняется локально.

### Редактирование

Редактор показывает поля записи один к одному. `id` сохраняется неизменным. Сохранение применяется атомарно; отмена оставляет состояние прежним. Выход из изменённой формы предлагает сохранить или отказаться от изменений.

### Удаление

Удаление сопровождается доступной отменой. Status-плашка с действием `Отменить удаление <id>` не исчезает автоматически и остаётся до следующей принятой операции, изменяющей набор, или явного закрытия пользователем. Удаление единственной записи лисы уменьшает число уникальных лис. Удаление последней записи всего набора переводит приложение в пустое состояние.

## JSON import и export — реализованный Phase 8 stretch

### Import

Основной import полностью заменяет набор после явного подтверждения:

```text
выбрать файл или вставить JSON
-> распарсить
-> проверить
-> показать preview
-> подтвердить замену
```

Preview показывает:

- количество записей;
- число уникальных лис;
- локации;
- диапазон времени;
- ошибки с адресом поля;
- предупреждение о замене текущего набора.

Одна ошибка делает применение недоступным. Текущее состояние и введённый JSON сохраняются для исправления.

### Boundary validation

- UTF-8 представление исходного file или paste — не более 2 MiB; превышение отклоняется до `JSON.parse`;
- корень — массив не более 1000 записей;
- `id` — уникальная непустая строка до 64 символов;
- `fox_id` — непустая строка до 64 символов;
- `fox_name` — необязательная непустая строка до 64 символов для совместимости со стартовыми и прежними сохранёнными данными;
- `location` и `color` — непустые строки до 80 символов;
- строки очищаются от окружающих пробелов;
- `has_prey` — строгий boolean;
- `suspicion_level` — конечное целое число от 0 до 10;
- `time` — реальное 24-часовое время `HH:mm`;
- повторяющийся `fox_id` допустим;
- пустой массив допустим после подтверждения;
- неизвестные поля считаются ошибкой контракта, чтобы import не терял данные молча.

Пользовательский текст выводится как текстовое содержимое. HTML-разметка из импортированных значений не интерпретируется.

### Export

Export создаёт JSON полного набора наблюдений в формате import. Активные фильтры не сокращают экспортируемые данные.

Артефакт называется `fox-dispatcher-observations.json`, использует UTF-8 и MIME `application/json;charset=utf-8`, сохраняет авторитетный порядок массива, форматируется двумя пробелами и завершается переводом строки. После запуска скачивания временный object URL освобождается. Эти детали делают round-trip и браузерный тест воспроизводимыми, не превращая порядок строк в часть расчёта.

## Локальное сохранение — should-have baseline

Состояние браузера содержит:

```text
schemaVersion
observations
scoringPolicy.preyWeightPercent
updatedAt
```

После перезагрузки восстанавливаются наблюдения и политика оценки. Фильтры начинают новую сессию сброшенными, чтобы сохранённая ограниченная выборка не скрывала данные при возвращении.

Стабильный ключ — `fox-dispatcher.dashboard`; версию задаёт envelope, а не имя ключа. Envelope проверяется строго: `schemaVersion` должен быть равен `1`, наблюдения проходят ту же схему, `preyWeightPercent` является целым от 0 до 100 с шагом 5, `updatedAt` является UTC ISO 8601 instant формата `new Date().toISOString()`, неизвестные поля запрещены. Результат загрузки различает `missing`, `valid`, `corrupt`, `unsupported-version` и `unavailable`; миграций в первой версии нет.

Baseline отличает отсутствующее, валидное, невалидное и недоступное сохранение. Невалидное или более новое значение не заменяется молча: autosave блокируется, точный raw value остаётся доступен в read-only поле, а переход к стартовым данным требует отдельного подтверждения. При недоступном storage или ошибке сохранения продукт продолжает работать с актуальным состоянием в памяти и сообщает, что изменения сохранятся только до закрытия страницы.

Сброс данных и сброс веса модели — разные действия. Сброс данных возвращает исходные пять записей после подтверждения; сброс веса возвращает 20% рядом с контролом.

## Состояния интерфейса

| Состояние | Результат и следующий шаг |
|---|---|
| Первый запуск | Стартовые 5 записей и полный рассчитанный отчёт |
| Пустой набор | Лидер отсутствует; доступны добавление, import и восстановление стартовых данных |
| Фильтры дали 0 | Исходные данные сохранены; видны область 0 из M и сброс фильтров |
| Ошибка формы | Краткое резюме и ошибки у полей; введённые значения сохраняются |
| Ошибка import | Путь и причина ошибки; текущее состояние не меняется |
| Невалидный baseline storage | Работа продолжается в памяти; доступно явное восстановление стартовых данных |
| Неизвестная версия storage | Autosave заблокирован; raw value доступен для выделения; переход к стартовым данным требует подтверждения |
| Storage недоступен | Работа в памяти с явным статусом несохраняемого состояния |
| Ошибка сохранения | Принятое состояние остаётся в памяти с явным memory-only статусом; полный набор можно экспортировать локально |
| Равные максимальные индексы | Все точные со-лидеры показаны в верхнем результате и объяснении; рейтинг сохраняет детерминированный порядок по tie-breaks |

Нулевой набор не создаёт фиктивного лидера с нулевым баллом.

## AI Worklog

AI Worklog доступен из основной навигации. Текущая согласованная версия содержит 6 фактических чекпоинтов. Карточка на сайте показывает:

- этап и дату;
- вопрос или цель;
- вклад AI;
- решение человека.

Публичный структурированный источник дополнительно включает:

- изменение продукта или репозитория;
- описание проверки;
- evidence-ссылки.

Worklog хранит краткий результат процесса вместо полной переписки. Секреты, токены, приватные абсолютные пути, клиентские данные и личная информация исключаются из публичного источника.

Каждое доказательство имеет структурированные `label`, `kind` и `href`. Ссылка ведёт на публичный HTTPS GitHub URL этого репозитория, закреплённый за commit/revision, либо на публичный Vercel artifact. Схема и разрешимость ссылок проверяются до сборки Worklog. Сайт намеренно не выводит `change`, `verification` и `evidence`: согласованные тексты и состав шести карточек остаются без изменений.

## Нефункциональные требования

- Статическое React-приложение развёртывается на Vercel.
- Пользовательские наблюдения остаются в браузере.
- Производственный runtime не требует backend или AI API.
- Основной сценарий работает клавиатурой.
- Интерфейс сохраняет функциональность при ширине 320 CSS px и увеличении 200%.
- Результат, состояние и ошибки доступны не только через цвет.
- Production build не содержит секретов, приватных путей и debug-артефактов.
- Production response headers ограничивают runtime собственными статическими ресурсами и запрещают сетевую отправку наблюдений.

Подробный accessibility и responsive контракт находится в [interface.md](../design-docs/interface.md).

## Приёмочные сценарии

1. Старт показывает 5 наблюдений, 4 лисы и Северную поляну 3/5.
2. При 20% добычи `fox_001` получает 7,8 и занимает первое место.
3. При 30% добычи `fox_003` получает 7,9 и занимает первое место; точный индекс `fox_001` равен 7,45 и отображается как 7,5.
4. Изменение `obs_005.suspicion_level` на 10 даёт `fox_004` 8,0 при политике 80/20.
5. Фильтр `Северная поляна` даёт 3 наблюдения и 2 лисы во всём отчёте.
6. Удаление единственной записи `fox_004` уменьшает число уникальных лис с 4 до 3.
7. Некорректный import сообщает адрес поля массива, например `[2].suspicion_level`, и не меняет текущий набор.
8. Корректный import применяется только после preview и подтверждения.
9. Перезагрузка восстанавливает данные и политику оценки.
10. Сброс возвращает исходные пять наблюдений, а отдельный сброс модели — вес 20%.
11. AI Worklog показывает 5-7 реальных public-safe checkpoints.
12. Публичный Vercel URL воспроизводит основной сценарий на desktop и mobile без console errors.
13. Выбранная лиса сохраняется при смене веса, но заменяется текущим лидером, если исчезает из активной выборки; фокус не перемещается.
14. Перестановка входных записей, равные времена и математически равные дробные индексы дают один и тот же порядок и отображение.
15. Import больше 2 MiB отклоняется до разбора, а future-version storage не заменяется стартовыми данными автоматически.

## Границы версии

Первая версия фокусируется на одном пользователе и одном локальном наборе наблюдений. Карта, координаты, синхронизация между устройствами, роли, аккаунты, серверная база, patrol workflow, runtime AI, прогнозы и вероятностная уверенность не входят в эту поставку.

Эти границы сохраняют проверяемость продукта: редактируемые вводные, прозрачная логика, живой результат, качественный интерфейс и видимый AI-first процесс.
