# Интерфейсная спецификация Fox Dispatcher

Статус: утверждённое направление для реализации

Продуктовый контракт: [fox-dispatcher.md](../product-specs/fox-dispatcher.md)

Архитектура: [../../ARCHITECTURE.md](../../ARCHITECTURE.md)

## Задача интерфейса

Аудитория — лесной смотритель, работающий с небольшой текущей выборкой наблюдений. Главная работа экрана — за несколько секунд ответить, какая лиса лидирует по индексу подозрительности, почему, где сосредоточены наблюдения и как проверить исходные записи.

Интерфейс ведёт от вывода к проверяемому расчёту:

```text
лидер -> точный балл -> вклады сигналов -> изменение данных
```

## Выбранное направление

Визуальная идея — **полевой журнал наблюдений, собранный как современный диспетчерский инструмент**.

Предметные источники формы:

- строки и поля карточки наблюдения;
- регистрационные метки времени и ID;
- спокойные природные материалы и цвета;
- диспетчерская ясность: выбранная сущность, приоритет, доказательство, действие.

Это светлый интерфейс с прохладным туманным фоном, бумажными рабочими поверхностями, тёмно-хвойным текстом, лисьим оранжевым для итогового сигнала и геодезическим синим для выбора и управления.

### Проверенные альтернативы

| Направление | Причина отказа |
|---|---|
| Map-first ranger console | Названия локаций не содержат координат; карта обещала бы отсутствующую точность |
| Тёмная security/SOC панель | Придаёт данным ложную угрозу и выглядит как универсальный risk-dashboard |
| Мультяшный волшебный лес | Ослабляет ощущение рабочего продукта и конкурирует с объяснением расчёта |
| Тёплый cream + serif + terracotta | Слишком близко к распространённому AI-generated editorial шаблону |

Прохладный полевой журнал сохраняет характер темы и профессиональную ясность.

## Ключевой элемент

Рабочая область связывает **Рейтинг лис** с двумя самостоятельными карточками справа. `Расчет индекса` показывает два округлённых до десятых вклада выбранной лисы, а `Вес параметров` содержит управление их соотношением. Исходные записи не дублируются в этих блоках: для их просмотра и изменения используется полный журнал в разделе `Параметры`.

### Типографика

| Роль | Шрифт | Использование |
|---|---|---|
| Display | Unbounded, variable | Название продукта и редкие короткие акценты |
| Interface | Onest, variable | Навигация, заголовки, тексты, формы, таблица |
| Data | `ui-monospace`, system fallback | `fox_id`, `obs_id`, время и формулы |

Onest и Unbounded поставляются локально из закреплённой зависимости или репозиторных font assets. Production UI не загружает шрифты с CDN.

Базовая шкала:

```text
Display mark     28-34 / 1.05
Page outcome     34-48 / 1.05
Section title    20-24 / 1.2
Body             16 / 1.5
Supporting       14 / 1.45
Data caption     12-13 / 1.4
```

Числа используют tabular numerals. Текст остаётся читаемым при пользовательском увеличении и изменении межстрочного/межбуквенного интервала.

## Информационная архитектура

Три адресуемых раздела:

1. `Сводка` — результат, рейтинг и методика расчёта.
2. `Параметры` — данные, фильтры, CRUD/persistence, import/export и recovery.
3. `AI Worklog` — фактические AI-first checkpoints.

Top-level navigation использует обычные ссылки с hash-состоянием, поэтому back/forward и статический reload сохраняют ожидаемое поведение на Vercel. Документ имеет `<html lang="ru">`. Первичная загрузка не перемещает фокус и не рисует программную обводку вокруг заголовка. Когда ссылка, back или forward действительно меняют destination, обновляются `document.title`, единственный `h1` и `aria-current="page"`, а фокус получает `h1` с `tabindex="-1"`. Если Back только закрывает sheet, destination не меняется и фокус возвращается его инициатору. Технические англоязычные фрагменты получают `lang="en"`, когда это требуется для произношения, а коды и ID остаются нейтральными.

Header содержит:

- компактный wordmark `Лисий диспетчер`;
- основную навигацию.

Обычный статус сохранения является контекстной частью раздела `Параметры` и не занимает место над результатом в `Сводке` или `AI Worklog`. Глобальная полоса появляется только при повреждённом, несовместимом или недоступном хранилище, когда отсутствие предупреждения создаёт риск потери изменений. Добавление, import JSON, export полного набора и восстановление стартовых данных находятся в разделе `Параметры`, где пользователь видит изменяемый набор и последствия операции.

Первые 900 px высоты отвечают на обязательные вопросы: количество лис, ведущая локация, лидер и причина. Блоки ниже развивают ответ, а не повторяют его.

### Outcome docket

Главная поверхность похожа на открытую диспетчерскую карточку, а не на generic KPI hero.

Содержимое:

- heading `Самая подозрительная лиса` без дополнительного route-label;
- читаемое имя крупным текстом и канонический `fox_id` рядом вторичным data-style текстом; при точной ничьей перечисляются все со-лидеры и все их `fox_id`;
- индекс `7,8 / 10`, собранный в один визуальный узел с именем лисы;
- объяснение результата как две компактные строки: `Средняя подозрительность по всем наблюдениям` и `Наличие добычи`, каждая со своей подписанной частью индекса и без повтора названия признака в значении; дополнительный видимый заголовок `Почему Лиса N` отсутствует;
- полноширинная полоса состава индекса с отдельными текстовыми обозначениями подозрительности, добычи и остатка до 10, поэтому смысл не зависит от цвета;
- компактная контекстная строка с числом уникальных лис и основной локацией вместо высокой боковой колонки;
- основное действие `Изменить параметры` открывает раздел `Параметры`, а визуально вторичная кнопка `Изменить вес параметров` переводит фокус на настройку добычи.

Начальная копия:

```text
Самая подозрительная лиса
Лиса 1 · fox_001 · 7,8 из 10
Средняя подозрительность по всем наблюдениям: 8,5 · 2 наблюдения · в индексе 6,8
Наличие добычи: в 1 из 2 наблюдений · в индексе 1
```

Термины `опасная`, `виновна`, `вероятность` и `AI confidence` не используются как описание результата.

Читаемое имя вида `Лиса 1` всегда сопровождается каноническим `fox_id`. Разные ID получают разные отображаемые имена: стандартный `fox_NNN` становится `Лиса N`, а нестандартный ID — `Лиса «<fox_id>»`. Если математически точный максимальный индекс разделяют несколько лис, outcome docket показывает полный список (`Лисы 3 и 5`, `Лисы 2, 3 и 5`) и отдельный подписанный именем лисы блок расчёта для каждой; округлённое совпадение без равенства точных дробей ничьёй не считается.

### Простое объяснение расчёта

Сразу после outcome docket находится отдельный блок `Расчет индекса подозрительности`. Первый полноширинный абзац сохраняет исходное пояснение о двух частях индекса. Второй объясняет, что количество наблюдений не добавляет баллы самостоятельно, но влияет на среднюю подозрительность и долю наблюдений с добычей. Третий добавляет: при стартовых настройках средняя подозрительность имеет 80% веса, наличие добычи - 20%; вес можно изменить ниже, а параметры наблюдений и количество лис - в разделе `Параметры`. После увеличенного вертикального отступа заголовок `Детальный расчет индекса самой подозрительной лисы` подписывает всю расчётную сетку над её верхней границей. Визуальная нумерация карточек отсутствует: три смысловых блока читаются по собственным заголовкам:

1. сколько наблюдений объединено, какова их средняя подозрительность и какой вклад она даёт при текущем весе;
2. в скольких наблюдениях отмечена добыча и какой вклад она даёт при текущем весе;
3. как два вклада складываются в итоговый индекс.

Для стартовых данных блок показывает `8,5 × 80% = 6,8`, `1/2 × 10 × 20% = 1` и `6,8 + 1 = 7,8 из 10`. Если один из результатов является периодической дробью, интерфейс показывает понятное десятичное значение до десятых, использует знак `≈` в формулах и прямо сообщает об округлении. Итог подписывается как результат без промежуточного округления, поэтому сумма двух округлённых вкладов не выдаётся за точное равенство. Рациональная арифметика остаётся внутренним источником истины для рейтинга.

На desktop три шага связаны видимыми знаками `+` и `=`, а итог выделен узкой сигнальной линией вместо тяжёлой заливки всей карточки. На мобильном экране шаги складываются вертикально, сохраняя тот же порядок и математические связи.

Граница блока прямо сообщает: `Цвет, локация и время в расчёте индекса не участвуют.`

### Scope toolbar

Панель начинается с текста `Показано лис: 4 из 4`. Значения `X` и `Y` считаются по уникальным `fox_id`: `X` - число лис в текущей выборке, `Y` - число лис в полном наборе.

В DOM и визуальной иерархии результат и его объяснение предшествуют панели фильтров. После route-focus на `h1` доступны два отдельных действия: `Изменить параметры` открывает раздел `Параметры`, а `Изменить вес параметров` переводит фокус на range-настройку `Влияние добычи`. На ширине до 640 px поля фильтров изначально свёрнуты под кнопкой `Показать фильтры`; подпись области и активные chips остаются видимыми.

Desktop-controls:

- поиск `Найти лису` по уникальному отображаемому имени или каноническому `fox_id`;
- single-select `Локация`;
- single-select `Цвет`;
- segmented control `Добыча: все / есть / нет`;
- `Сбросить всё`, когда область отличается от полной.

Добыча реализуется как `<fieldset>` с `<legend>` и radio group. Активные значения дополнительно отображаются removable chips с доступными именами вида `Удалить фильтр Локация: Северная поляна`.

`Найти лису` выполняет регистронезависимый поиск по отображаемому имени или `fox_id` после удаления окружающих пробелов. Полное совпадение с именем или ID имеет приоритет над поиском по подстроке, поэтому `Лиса 1` не захватывает `Лису 10`. Локация и цвет выбираются точным совпадением из вариантов полного набора; уже выбранное значение не исчезает при применении другого фильтра. Эти правила относятся только к report scope и не меняют регистрозависимую группировку лис.

### Рейтинг

Desktop использует семантическую таблицу или список строк с табличной структурой:

```text
Место | Лиса | Индекс | Основание | Последнее наблюдение | Наблюдений
```

Строка содержит понятный текст причины: `оценка 8,5 · добыча в 1 из 2` и полное количество `2 наблюдения`. Цвет лисы представлен текстом с маленьким swatch. Выбранная строка имеет синий structural marker и `aria-selected` только если реализация использует подходящий composite pattern; для обычной таблицы выбор выполняет кнопка-ссылка с ясным доступным именем.

Сортировка рейтинга следует доменной модели. UI не добавляет клиентскую пересортировку, способную изменить tie-break. Tie-break определяет стабильный порядок строк с равным индексом, но все лисы с точным максимальным индексом получают состояние лидера и остаются перечислены в верхнем результате.

При первом непустом отчёте выбран лидер. Явно выбранная строка остаётся выбранной при изменении веса, даже если лидер сменился, пока лиса остаётся в области отчёта. Если фильтр, удаление или import исключили её, выбирается текущий лидер; пустая область показывает empty inspector. Автоматическая смена не перемещает фокус и объявляется через общий polite status.

### Расчёт выбранной лисы и вес параметров

Под заголовком `Рейтинг лис` находится инструкция `Выберите лису для отображения расчетов.`; отдельный eyebrow над рейтингом отсутствует. Правая колонка разделена на две визуально и семантически самостоятельные карточки:

1. `Расчет индекса` — имя выбранной лисы, индекс и две строки вклада с числами;
2. `Вес параметров` — контрол влияния добычи и сброс стартовых значений.

Инспектор остаётся read-only. Просмотр исходных записей и редактирование выполняются в разделе `Параметры` в контексте полного журнала.

Вклад выражен текстом и пропорциональной полосой. Декоративная длина имеет `aria-hidden`, а рядом остаётся полная арифметика. Все пользовательские значения выводятся единообразной десятичной записью до одного знака; для периодических результатов формула использует знак `≈` и пояснение об округлении.

Контрол веса объединяет:

- `<input type="range">` с подписью `Влияние добычи`;
- синхронизированный numeric/step control как альтернатива перетаскиванию;
- текущие подписи `Влияние подозрительности 80%` и `Наличие добычи 20%`;
- краткую инструкцию `Измените вес параметров`;
- действие `Сбросить значения`.

Numeric control хранит локальный текстовый draft, поэтому допускает пустое промежуточное состояние и последовательный ввод `3`, затем `30`. Значение применяется по `blur` или `Enter` только для целого диапазона 0–100 с шагом 5; постоянный hint и ошибка связаны с полем через `aria-describedby`.

Preview меняется во время управления. После `pointerup`, `blur` или короткой стабилизации клавиатурных шагов один polite live region сообщает итоговый вес, лидера либо полный набор со-лидеров и индекс, даже если результат не сменился. Серия промежуточных положений slider не создаёт поток объявлений.

## Параметры

### Desktop table

```text
Время | Лиса | Локация | Цвет | Добыча | Оценка | Действия
```

Таблица имеет `caption`, column headers и сортировку только представления исходных записей — она не влияет на report scope или рейтинг. По умолчанию используется `time` по убыванию, затем `id` по возрастанию. Заголовки времени, лисы, локации, цвета, добычи и оценки содержат `<button>`; повторное нажатие меняет направление, вторичный tie-break всегда `id` по возрастанию. `aria-sort` находится только на текущем `<th>`. Действия строки доступны по отдельной кнопке с именем наблюдения, например `Изменить obs_005`.

### Mobile cards

На узком экране запись становится карточкой:

```text
12:10  obs_005
fox_004                         3 / 10
Северная поляна · рыжая
Без добычи
[Изменить]
```

Карточки сохраняют полный текст и не требуют горизонтальной прокрутки.

Над mobile cards находится labelled control `Сортировка наблюдений` с теми же полями и направлениями, что desktop headers. Начальное значение — `Время: сначала поздние`; смена порядка переставляет только cards и не влияет на report scope или рейтинг. Вторичный tie-break остаётся `id` по возрастанию.

### Observation editor

Desktop: доступный dialog или right-side modal sheet, выбранный по результату проверки реального потока.

Mobile: near-full-screen modal dialog with a small viewport inset so that the modal boundary and underlying context remain perceivable.

Порядок полей:

1. `Имя лисы` — text input с существующими именами как suggestions; `fox_id` создаётся или переиспользуется автоматически;
2. `Локация` — text input с существующими вариантами как suggestions;
3. `Цвет` — text input с suggestions для новой лисы; при точном совпадении существующего имени поле автоматически получает закреплённый цвет, становится read-only и связывается через `aria-describedby` с неблокирующим status-сообщением `Для данной лисы уже задан цвет XXX`;
4. `Добыча` — два radio options;
5. `Оценка подозрительности` — number 0-10;
6. `Время` — native time input;
7. технический `id` — read-only при редактировании; для новой записи до первого принятого сохранения показано `ID будет создан автоматически`.

Manual editor и import используют ту же observation schema, что bundled starter boundary: trimmed required strings, максимальные длины 64/80, strict prey choice, целое `suspicion_level` 0-10 и реальное `HH:mm`. Ограничения показаны постоянными hints и программно связаны с полями.

Footer: `Отменить` и `Сохранить наблюдение`. Удаление находится в отдельной secondary зоне и называет объект: `Удалить obs_005`.

При сохранении существующее имя повторно использует связанный `fox_id`. Новое имя и новая запись получают первые свободные `fox_NNN` и `obs_NNN`; числовые пропуски заполняются раньше следующего максимального номера. Имя сохраняется независимо от технического ID.

При неуспешной отправке фокус получает summary `Проверьте 2 поля` с `tabindex="-1"`; каждый пункт summary является ссылкой на поле. Поля используют `aria-invalid` и `aria-describedby`. После успешного сохранения фокус возвращается к обновлённой записи или к кнопке добавления для новой записи. Подтверждение выхода с несохранёнными изменениями использует тот же dialog focus/return contract.

Удаление показывает status-плашку `Наблюдение obs_005 удалено` с кнопкой `Отменить удаление obs_005`. Она не исчезает автоматически и остаётся до следующей принятой операции, изменяющей набор, или явного закрытия. Фокус после удаления переходит к логически соседней записи; status объявляется один раз и не перехватывает фокус.

### Import dialog — реализованный Phase 8

Шаги оформлены как реальные состояния процесса:

1. `Добавить JSON` — file input или textarea;
2. `Проверить данные`;
3. preview числа записей, лис, локаций и диапазона времени;
4. `Заменить текущие данные`.

Ошибки показываются списком с адресом, например:

```text
[2].suspicion_level — ожидается целое число от 0 до 10
```

Превышение pre-parse лимита показывает focused summary `JSON больше 2 МиБ` и пояснение `Выберите меньший файл или сократите вставленный текст`; parse и preview не запускаются, введённый paste сохраняется. Для file input сохраняется имя файла, но не обещается повторное чтение без нового выбора браузером.

Системный file input скрыт за локализованным действием `Выбрать JSON-файл`; рядом показано русское состояние чтения и имя выбранного файла. Асинхронное чтение защищено ревизией источника: более поздний выбор файла или ручное изменение textarea всегда остаётся авторитетным, а завершившееся старое чтение не может заменить новый draft или preview. Текст, имя файла и измеренный размер образуют одну provenance-запись. Нечитаемый файл не получает старый текст или размер: старый draft остаётся видимым, preview исчезает, а повторная проверка блокируется до ручного изменения draft или успешного выбора другого файла.

Кнопка замены появляется доступной после успешной проверки. Закрытие и повторное открытие в рамках текущей попытки сохраняет введённый текст, пока пользователь явно его не очищает.

### Export action — реализованный Phase 8

Действие `Экспортировать все наблюдения` всегда называет полный набор и не зависит от текущих chips. Оно скачивает `fox-dispatcher-observations.json`; успешный запуск получает polite status `Экспорт подготовлен: N наблюдений`, а ошибка создания файла сохраняет данные и предлагает повторить действие.

## AI Worklog

Worklog выглядит как последовательность фактических checkpoints, где нумерация имеет реальное значение.

Каждый checkpoint содержит:

```text
Этап и дата
Что нужно было решить
Чем помог AI
Какое решение принял человек
Что изменилось
Как проверено
```

Evidence отображается ссылкой с человеческим названием: `План реализации`, `Decision 0001`, `Тест scoring`, `Mobile screenshot`, `Vercel deployment`.

UI использует только проверенные публичные HTTPS evidence references, закреплённые за GitHub revision или Vercel artifact. Текст ссылки описывает доказательство; raw filesystem path или изменяемый branch URL пользователю не показывается.

Checkpoint с найденной ошибкой появляется после фактической проверки. Полная переписка и приватные пути в UI не включаются.

## Responsive behavior

### Desktop: 1200 px и шире

- 12-column content grid;
- ranking занимает 7 колонок, inspector — 5;
- outcome docket и обязательные ответы помещаются в первый viewport 1440×900;
- inspector может быть sticky внутри секции при сохранении доступности focus.

### Tablet: 768-1199 px

- outcome docket сохраняет две колонки;
- ranking и inspector переходят в последовательность 7/5 или stacked в зависимости от доступной ширины содержимого;
- navigation остаётся сверху;
- location activity и recent observations располагаются друг под другом.

### Mobile: 320-767 px

- верхний header содержит только wordmark; destination links находятся в нижней навигации;
- три destination links переходят в нижнюю навигацию;
- раздел `Параметры` сохраняет заметное действие добавления, а вторичные starter recovery/import/export раскрываются кнопкой `Показать управление данными`; аварийная recovery-панель всегда предшествует обычной панели данных;
- outcome docket становится одной колонкой: лидер, причина, затем сводные числа;
- ranking становится набором cards;
- inspector сохраняет stacked layout, а поля фильтров сворачиваются под компактной кнопкой после видимого результата;
- рядом с контролом политики остаётся компактный текущий лидер либо полный список со-лидеров и индекс, чтобы пересчёт не требовал прокрутки к верхнему outcome docket;
- editor использует mobile dialog/card treatment, а import — почти полноэкранный native dialog;
- на странице отсутствует горизонтальный overflow.

Bottom navigation не перекрывает focus: основное содержимое получает соответствующий нижний padding, а focused controls прокручиваются в видимую область.

Каждый фактически реализованный inspector, filter, editor или import sheet/dialog имеет доступное имя, явную кнопку закрытия, Escape и возврат фокуса инициатору. Browser Back закрывает route-aware editor/sheet до смены destination. Initial focus задан явно:

- inspector — на heading выбранной лисы с `tabindex="-1"`;
- filters — на heading `Фильтры` с `tabindex="-1"`;
- add/edit editor — на первом editable поле `Лиса`;
- import — на textarea `JSON наблюдений`, одинаково пригодном для paste и загруженного файла;
- unsaved-changes и destructive confirmation — на безопасном действии `Продолжить редактирование` или `Отмена`.

Если Phase 6 evidence обосновывает filter sheet, он хранит draft отдельно: `Сбросить` очищает только draft и обновляет число в `Показать N наблюдений`; эта кнопка применяет draft, а закрытие или `Отмена` оставляет действующую область прежней.

## Interaction feedback

### Live updates

Один `aria-live="polite"` announcer сообщает значимые результаты. На сводке последнее принятое изменение дополнительно остаётся видимым обычным текстом, чтобы пересчёт можно было проверить без чтения live region:

- `Вес добычи изменён с 20% до 25%. Лидер не изменился: Лиса 1, идентификатор fox_001, индекс 7,6.`
- `Вес добычи изменён с 20% до 30%. Новый лидер — Лиса 3, идентификатор fox_003, индекс 7,9.`
- `Наблюдение obs_005 сохранено. Теперь лидирует fox_004, 8,0.`
- `Фильтры применены: 3 лис из 5.`

Он не читает заново весь рейтинг и не дублирует каждое промежуточное положение range input.

Одна принятая команда создаёт одно атомарное сообщение. Если фильтр одновременно меняет scope и selected fox, announcer объединяет оба результата, например: `Фильтры применены: 3 лис из 5. Выбрана лиса fox_001.` Отдельное fallback-сообщение не перезаписывает первое.

### Motion

- 150-200 ms для раскрытия sheet и изменения selected marker;
- bar lengths переходят к новому значению без bounce;
- сменившийся лидер получает один короткий outline pulse;
- `prefers-reduced-motion: reduce` переводит изменения в мгновенные состояния;
- autoplay, parallax и ambient animation отсутствуют.

### Focus

- первый элемент страницы — skip link к `<main>`;
- navigation, filters, ranking actions and data actions follow visual order;
- native dialog или эквивалентный tested pattern удерживает focus;
- Escape закрывает secondary surfaces и возвращает focus инициатору;
- после удаления focus переходит к логически соседней записи;
- после удаления filter chip фокус переходит к следующему chip, затем к предыдущему, а при их отсутствии — к `Сбросить фильтры` или heading области отчёта;
- если применение фильтра дало ноль, фокус остаётся на вызвавшем обновление контроле, а `0 из M` сообщается через polite status; heading состояния получает фокус только после явного перехода пользователя.

## Empty, error, and recovery copy

| Состояние | Заголовок | Действия |
|---|---|---|
| Нет данных | `Наблюдений пока нет` | `Открыть управление данными` ведёт к `Добавить наблюдение`, `Импортировать JSON`, `Вернуть стартовые данные` |
| Фильтры дали 0 | `В этой выборке ничего не найдено` | `Сбросить фильтры` |
| Import error | `JSON содержит ошибки` | Исправить перечисленные поля; текущий отчёт сохранён |
| Import oversized | `JSON больше 2 МиБ` | Выбрать меньший файл или сократить вставленный текст; текущий отчёт сохранён |
| Storage corrupt | `Сохранённые данные повреждены — автосохранение приостановлено` | Показать/выделить raw JSON или подтвердить удаление сохранения и starter recovery |
| Storage unsupported | `Сохранение версии N не открыто — автосохранение приостановлено` | Показать/выделить raw JSON или подтвердить удаление сохранения и starter recovery |
| Storage unavailable | `Изменения сохраняются только до закрытия страницы` | Продолжить в памяти или экспортировать полный набор |
| Storage save failed | `Не удалось сохранить — изменения останутся до закрытия страницы` | Продолжить в памяти или экспортировать полный набор |

Тексты называют причину и следующее действие. Ошибки не очищают пользовательский ввод.

## Accessibility acceptance

Целевой уровень — WCAG 2.2 AA для применимых сценариев.

### Semantics and reading order

- `header`, labelled `nav`, `main`, sections and descriptive headings;
- один `h1` отражает текущий destination;
- документ имеет русский `lang`, описательный title и фокусируемый route heading при hash-навигации;
- skip link открывается при focus;
- heading order и DOM order совпадают с визуальной последовательностью;
- charts and status marks have exact textual equivalents.

### Keyboard

- весь reviewer journey выполняется Tab, Shift+Tab, Enter, Space, arrows for native range, and Escape for dismissible surfaces;
- custom drag-only interactions отсутствуют;
- slider имеет numeric alternative;
- target size минимум 24×24 CSS px, основные действия — около 44 px;
- focus indicator заметен и не перекрывается sticky header/bottom navigation.
- ориентация viewport не блокируется; essential content не существует только на hover или focus.

### Forms and errors

- каждое поле имеет постоянный visible label;
- обязательность всех полей объявлена видимым текстом, а native controls используют `required`;
- instructions связаны через `aria-describedby`;
- invalid fields use `aria-invalid` and field error IDs;
- error summary receives programmatic focus after failed submit;
- destructive reset and dataset replacement require review/confirmation;
- delete supports undo.

### Dynamic results

- changed leader and accepted mutations use polite status messages;
- urgent validation failures use a focused summary rather than repeated assertive announcements;
- loading skeleton is unnecessary for synchronous local startup;
- no real result is represented as an unexplained zero during invalid state.

### Visual access

- text contrast target 4.5:1;
- large text and non-text control boundaries target 3:1;
- 200% text resize retains functionality;
- 320 px reflow has no page-level horizontal scroll;
- WCAG text-spacing preset сохраняет контент и действия при `line-height: 1.5`, paragraph spacing `2em`, `letter-spacing: 0.12em`, `word-spacing: 0.16em`;
- labels, numbers, icons, and patterns supplement color;
- reduced motion and increased contrast preferences receive explicit styles.

### Verification matrix

| Check | Evidence planned |
|---|---|
| Keyboard reviewer journey | Playwright keyboard flow plus manual pass |
| Dialog focus and return | Focus assertions in component/browser tests |
| Table sort semantics | Component assertion for `aria-sort` |
| Form errors | Label, description, summary, and focus assertions |

| Contrast | Token pair audit and browser tooling |

| Sheets and filter draft | Accessible name, initial/return focus, Escape, Back, apply/cancel assertions |

| Motion and contrast preferences | Reduced-motion and forced/increased-contrast browser checks |

## Design review checkpoints

Implementation screenshots are reviewed at:

1. walking skeleton — hierarchy and real starter copy;
2. interactive ranking — selected-fox calculation and contribution clarity;
3. CRUD/persistence/import/recovery — forms, states, focus, reload, atomic replacement, download, and raw preservation;
4. responsive polish — 1440×900, 768×1024, 390×844, and 320 px;
5. Vercel preview — production fonts, layout, console, network, and public Worklog.

The visual review asks whether the interface still reads as a field observation product when the logo is hidden. The language, data density, and ledger structure should carry that identity without decorative forest imagery.
